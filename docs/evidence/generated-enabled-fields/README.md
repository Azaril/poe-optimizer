# Generated enabled-field checkpoint

October 21, 2026. This extends the
[earlier generated-field checkpoint](../generated-firebolt-dispositions/README.md).
The [implementation plan](../../implementation.md) remains the current resume point.

The Import adapter can account for an exact generated group or Gem `enabled="true"`
without discarding its separate typed participation destination. Both the raw and
decoded tokens must be literal `true`. False, missing, `nil`, escaped or unknown
tokens do not obtain this receipt. Exact source, provider, output and consumer
checks still apply. This is an Import responsibility; native evaluation gains no
Lua token handling, source dispatch or PoB UI behavior.

The reviewed Original05 Firebolt packet now has fifteen intrinsic destinations.
The two enabled fields replace only their Deferred destinations; both typed
participation values remain true. Reporting remains independently false. Four
fields remain Deferred on the selected source: group `mainActiveSkill` and
`mainActiveSkillCalcs`, and Gem `count` and `enableGlobal2`. Its unresolved Sol Pole
alternative still has nineteen Deferred fields. Neither count is the build's
selected issue count, which remains five. No complete native build is claimed.

## Evidence boundaries

The optional source suite authenticates exact pinned PoB components and exercises
their enabled consumers, including generated-source lifecycle, support dispatch,
GroupProperty, socket delivery, counts and requirements, Thorns, EnergyBlade and
assignment counts. Literal true is nonrestricting in these tested paths; it does
not establish absent consumers, complete source topology or unconditional
activation. Fresh/JIT controls are component evidence, not full-build parity.

Synthetic Rust Import tests exercise private receipt consumption and independent
consumers. The real-build publication gate separately checks persisted bindings,
providers and origins, whole outputs, all five selections, replay and rebuild. It
does not directly observe private receipts in the original builds. Ordinary CLI
checks authenticate bundled evidence without loading Lua or requiring a PoB
checkout. Numerical evaluation is outside this checkpoint.

The embedded source proof is deliberately the immutable `tests-pending` authoring
record. Actual executions and their log hashes belong in the separate validation
receipt; changing the authoring status after execution would change its seal.
