# Next generated-source adapter: closest Original05

Read-only audit, October 21. This is implementation guidance after the required
reverse-primary census checkpoint; it grants no Import completion or native
coverage and records no new runtime pass. Root owns serialized Cargo validation.

## Existing seams and bounded change

Use the current private generated `CheckedInputDisposition` in
`crates/poe-optimizer-import/src/owned_normalize/generated_skill_inputs/dispositions.rs`.
Its same-attempt `matches_current` check already binds exact source/group/preset,
provider records, raw-input binding and materialized usage outputs. Archived
syntax cannot produce this receipt.

Add one reusable private generated catalog-singleton check, without new public
policy or native model:

1. Resolve the correspondence's exact effect ID and owned Skill through
   `OwnedSkillRoleIndex::reverse_primary`.
2. Require `Observed` with exactly one candidate, matching the correspondence's
   Gem and the observed construction's catalog key. Unavailable, missing route,
   wrong owned Skill, observed zero and multiple candidates do not prove this
   catalog-backed path.
3. Join the exact saved Gem tuple and mapped primary to the construction. Require
   only that primary in the constructed/resolved effect list, no additional or
   missing effect references, and no alternative display position. Additional
   stat sets alone do not create another effect.
4. Retain the existing live provider, source, slot, saved/provider level, preset,
   one-child group and output checks. Charge lookups, comparisons and traversals
   before doing them, using the existing bounded Import accounting pattern.

The census now spells the unavailable Rust variant `Unavailable {}`. Root made
this strictness correction after the initial catalog run was 34 pass / 1 fail:
Serde's internally tagged unit variant ignored unknown fields. The empty struct
variant preserves the wire representation and retains the failing strict test.
The correction's later validation is owned by root, not claimed here.

## Independent field responsibilities

**Group `mainActiveSkill` and `mainActiveSkillCalcs`:** extend the existing
`usage_inputs/inventory/group_selectors.rs` proof for one exact live Generated
receipt. It currently rejects a group `source` attribute and Generated identity.
Account each present selector only when raw and decoded values are exactly
`nil` or `1`; do not fabricate absent fields. Preserve existing physical and
manual Direct paths. This is reference selection only, not admission or execution.

**Gem `enableGlobal2`:** the same proven singleton route can establish that a
present literal raw/decoded `true` or `false` is unread. Keep the current private
receipt machinery and all other consumers conjunctive. Do not borrow the
physical-only helper's authority merely because its construction predicate is
similar. Missing, escaped or unsupported values remain outside this new proof.

**Gem `count`:** combine the route proof with existing
`usage_inputs/occurrences.rs::counts_accounted` and the exact typed usage receipt.
The source's `getActiveSkillCount` uses a present group override, including zero,
then the matching catalog Gem's count or one; direct fallback returns one.
Retain the independent `326a/326b` usage destination when replacing the Deferred
field responsibility. Malformed shadowed Gem count cannot be hidden by a valid
group override. Selector neutrality, especially across group replacement, does
not establish saved count retention.

## Source evidence and limits

`owned_generated_source_dispatch_source.rs` observes the complete injected
catalog and actual dispatchers. `LoadSkill` and generated construction use
Skill-table-keyed reverse lookup. Bare `ProcessSocketGroup` uses string-keyed
lookup and can take the direct-effect fallback. Deleting a map entry can produce
the same direct shape despite a real candidate, so output shape is not evidence
of observed absence. Alias order cannot be promoted to winner authority.

Existing `owned_secondary_effect_switch_source.rs` generated controls separately
exercise matching-group count preservation, group overrides, unread secondary
switches, independent selectors, zero/one admission and actual replacement.
Its earlier restricted catalog is not complete reverse-census evidence; combine
the proved consumer law with the complete-catalog dispatch evidence, rather than
treating either as sufficient alone. Replacement-neutral selector controls do
not prove saved count, quality or participation retention.

Firebolt has one effect plus an additional stat set. Djinn summon routes have two
effects including Command; this singleton adapter must not erase or account for
their unresolved second-effect responsibilities.

## Focused test and publication scope

- Extend `tests/support/owned_generated_field_accounting.rs` using compiler-derived
  singleton roles/census and the existing synthetic exact Tree/Item providers.
- Keep lexical-only refusal meaningful with Unavailable observations. Add zero,
  alias ambiguity, wrong Skill/candidate, missing/additional effects, reordered
  display, stale live outputs/providers, cross-provider borrowing and archived
  preset controls. Full catalog reproduction remains mandatory at publication.
- Cover independent nil/1 selector lanes, unsupported and escaped tokens,
  secondary true/false, count 1/3, group override 0/4 and malformed shadowed count.
  Missing fields must not be mistaken for receipts or fabricated defaults.
- Preserve whole-draft and sidecar inverses, unchanged independent raw/count
  values, exact consumers and atomic work-limit failure. Reuse the patterns in
  `tests/support/owned_direct_group_selectors.rs` and the existing private receipt
  mutation tests rather than creating another framework.
- Update the live Firebolt row in `generated-firebolt-dispositions` only for
  fields proved by the adapter; retain all typed consumers. Keep Sol Pole,
  unrelated fields, native rules and mechanical coverage unchanged. Reuse the
  current publication helper and whole-five preservation gate.

The live packet currently leaves four Deferred responsibilities: the two group
selectors, Gem count and Gem secondary switch. Retiring these field destinations
does not itself establish whole-preset completion or a complete native build;
the existing complete inventory gate decides any actual issue retirement.
