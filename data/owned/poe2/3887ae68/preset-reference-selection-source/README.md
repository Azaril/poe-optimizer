# Preset reference selection source components

This is source evidence for a future Import accounting rule. It changes no
normalization policy, native state, definition coverage or build admission.
Current Original05 group selectors are absent, `nil` or `1`; the proposed rule
for that finite domain is **not implemented or certified by this packet**.

The ordinary optional-PoB package target
`owned_preset_reference_selection_source` authenticates nine complete pinned
source bodies, the original XML, the current source catalog, exact declaration
spans and consumer boundaries. It reads the pinned submodule through the
existing source verifier; there are no Git, network, subprocess or `runs/`
dependencies. The previously missing BuildExport module is also retained in
`BuildExportPoE2.lua.gz`. The existing authenticated upstream license is reused.
`authoring.json` seals the packet; the Rust target pins that seal independently.

Eight full primary Skill declarations, two real Djinn Command declarations,
source constants, modifier constructors, the full Gems data table and
`Data.setupGem` execute under mlua/LuaJIT. The actual CalcSetup iteration and
admission predicate, its group-selection block, SkillsTab selector loading,
and BuildExport reference consumers execute unchanged in explicit host
wrappers. Each behavioral test creates fresh VMs for JIT disabled and enabled.

## Boundaries of the execution

These are **isolated source-component tests**, not a complete PoB evaluator
oracle or evidence of complete build parity. The wrapper replaces the body
after the admission predicate with identity-only `activeSkill` objects.
It never calls `calcs.createActiveSkill`, computes a number, initializes lazy
stat-map metadata, reconstructs an item/tree provider, or establishes that
every downstream effect is ready. Cosmetic `copyTable` support and source
identity initialization are explicit host infrastructure.

Actual full declarations provide support/hidden metadata. Synthetic controls
then change those fields, participation, global metadata, or source order.
Their results establish behavior of the executed source components only.
In particular, setting `hasGlobalEffect=true` is a synthetic input, not a
claim that the complete evaluator produced that value for these skills.
Current `enableGlobal1=true` admits either metadata state; it does not make
the setting inert or prove any other consumer accounted for.

The eight families cover the ten remaining exact group/primary pairs from
Original05. XML ordinals and every saved attribute are authenticated separately
from the synthetic controls. Real current declarations place the primary first.
Four skeletal additional Command references remain explicitly declared and
unresolved in the pinned catalog. Observing the admitted first primary does not
certify those later definitions absent, inert or supported.

## Controls and future work

Controls cover actual display-order rewriting, repeated identical Gems with
distinct physical identities, hidden/support/disabled primaries, global gates,
the loader's absent/`nil`/`1` behavior, independent MAIN/CALCS selectors, the
exporter's MAIN-only selection, and source upper-only clamping.
Out-of-domain malformed, zero, negative, fractional and oversized selections
are source observations, not accepted Import semantics. The empty-list test
refuses a selected target; the later MeleeUnarmed fallback is retained as source
evidence and is not executed or imported.

The future importer still needs exact current Skill/provider/preset/group
receipt binding, source admission and field-accounting authority, stale and
ambiguous provider controls, and whole-inventory completion checks. This packet
does not create any such authority. Native explicit query targets, participation
and raw export data remain separate from source reference selection.
