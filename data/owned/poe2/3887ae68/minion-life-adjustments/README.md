# Original minion Life adjustment census

This packet retains source evidence only. It publishes no native definitions,
programs, defaults, query closure or final Life consumer. The selected recipient
is the actual Skeletal Sniper actor in the unchanged Original05 build and six
existing source controls. Authored native admission must preserve the exact
source occurrence and recipient; the profile name is not runtime dispatch data.

The original Life function runs three times for each executed minion, from
`CalcDefence.lua` lines 998, 1189 and 1631. The retained projection preserves all
three calls in order, complete call records, their raw modifier records, source
occurrences and exact actor/store identity. It preserves relevant hooked and
independent unhooked snapshots separately. An unexecuted CALCS actor remains
unexecuted; its missing Strength/output is never converted into an observed zero.

The raw inventory contains genuine zero-valued suppliers:

- Every executed call retains a `Life BASE 0` record from `Strength`. The witness
  observes its original insertion at `CalcPerform.lua:506`, the exact record
  object, its position and its survival in the actor store. Its supplemental
  tabulation omits the zero record. Original final Strength is zero; raw `Str`
  and `Attributes` inventories are empty and the five inherent bonus flags are
  absent in these controls.
- The first two calls have no `ExtraLife` or `LifeTotal` records. Before the third
  call, each gains a `BASE 0` record from `Conversion`. Their source identities,
  order and original consumer values are retained. This does not validate the
  transformation formulas or their incoming donor inventories.
- The three outgoing Life conversion channels and their pre-cap combined query
  have no records here. Life override and Chaos Inoculation are absent. These
  observations do not authorize zero defaults for untranslated native sources.

Supplemental channel queries are explicitly identified as observations. Original
consumer locals, final return values and later output remain separately recorded;
no copied arithmetic produces an oracle result. Original05 retains Life 2791
from its observed components, without claiming native formula parity.

`e7f5ffe21ff79d9ade559232337b7cd07419282603467889e48ce2e6edde9c62`.
Both configured JIT modes agree exactly. The instrumented observer itself runs

`evidence/observer.lua` contains the exact 67,296 source-observer bytes whose hash

`41841678b5a265833e8e24adad4a6540bc6aacb3abaa305269f29e8b5d260a2d`.
This archive is read only for hash verification; it is never executed or used as
a compatibility fallback. New acquisitions use the current source observer.
The pinned upstream manifest and complete relevant file-hash inventory remain
part of the retained projection. No earlier packet or report is rewritten.

The initial checker incorrectly expected both additional-Life buckets to remain

when that assertion failed. The strengthened checker validates the actual staged
zero suppliers against that retained report and the completed on report before
authoring this packet; no repeat-until-pass source acquisition was used.

## Validation

The ordinary Rust tests in
`crates/poe-optimizer-pob/tests/support/minion_life_adjustments_evidence.rs` reuse
the parent source checker. They authenticate the projection, source manifest and
archived observer, then reject missing, duplicated, reordered or misplaced zero
records; zero overrides; absent/nonempty attribute inventories; missing conversion
inventories; conflicting consumer values; substituted Player identity; and
unexecuted CALCS disguised as an observed empty domain.

The ignored `life_adjustments::evidence::retained_full_reports_authenticate_the_exact_projection`
test must pass locally before admitting this evidence. It authenticates both
complete report bytes, runs the current checker on each, and regenerates the
projection with exact `serde_json` values. It requires no PoB VM. The separate
explicit authoring test refuses to overwrite an existing packet.

Run the `owned_minion_physical_damage_source` target through the project's serial
Cargo lane. The `life_adjustments::evidence::` filter runs the ordinary checks;
the retained-report test uses `--ignored --exact`. Full source replay and the
parent retained-report checker remain separate opt-in tests. This evidence does
not complete inherent-attribute or resource-transformation mechanics, numerical
domain validation, owner coverage, or an original build.
