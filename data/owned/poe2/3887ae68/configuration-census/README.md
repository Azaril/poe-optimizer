# Configuration source census

This is the maintained finite source inventory for configuration completion.
It is evidence for reviewing Import assignments, not a Complete inventory or a
native mechanic definition. Production still has 38 disposition rules and no
configuration inventory; this packet retires no build obligation.

The source revision is `3887ae68a6a6b8bb7b41d1b61998f1aa184201e4`.
[evidence.json](evidence.json) authenticates the source manifest, unchanged
Original05, three data artifacts and 28 complete source files. Twenty files
reuse existing tracked evidence; eight additional gzip archives retain the
remaining files. Stored and expanded byte counts and SHA-256 hashes are separate.
Source text uses the manifest's CRLF-to-LF normalization.

There are 564 named occurrences and 563 distinct names. Both
`conditionEnemyExitedPresenceRecently` declarations remain separate at rows 523
and 524, including their different callbacks. All 99 unnamed structural rows
remain in order. The Rust projection removes only the local checkout prefix from
function paths; pinned `src/...` path, kind and inclusive line range remain exact.
It translates no source value or callback into native semantics.

Direct accesses retain file, line, column, per-line occurrence identity, exact
expression and full source line. Adapter-name correspondence is an inspection
aid, not proof of accounting for every consumer. Missing catalogue membership
does not remove `PvpScaling` or `multiplierManaBurnStacks`. Computed families
retain non-UI Physical/Chaos keys and the actual `enemyPhysicalenemyOverwhelm`
Placeholder spelling. Every `admission_proved` marker remains false.

The initial inspection searched four explicit Config carriers across 1,069 Lua
files. That lexical census and twelve alias reviews do not establish arbitrary
whole-program alias closure. This packet is not a Lua parser or an automatic
absence classifier.

## Reproduction

The existing PoB test `owned_configuration_inputs_source.rs` runs normal loads
with original business methods. Its unchanged Lua observer captures the actual
ordered `BuildModList` catalogue and checks method identities and read-only
observation. The Rust child `support/configuration_census_source.rs` compares the
full portable catalogue against this packet for every successful original and
control load, then writes a small receipt beside the complete report. The test
attempts five originals and 28 controls independently with JIT off and on; the
existing full-report equality check remains mandatory.

The initial projection used the historical **23-case** report identified in
`evidence.json`. That identity remains historical provenance, not a claim that
the old report contained 29 cases. The first maintained **29-case** verification
is retained under `acquisition.previous_verifications`: all 29 cases reproduced
the catalogue in each mode, and the complete 37,752,151-byte reports agreed at SHA-256
`b16d8d172a2f9b60f78d3efe082c40bfbee1913d1b5eb2f797574fb3631b47f7`.

Fresh **33-case** verification includes four dispatcher contrasts. All 33 loads
reproduce the same full catalogue in each mode. The complete reports are
byte-identical, each 42,992,270 bytes with SHA-256
`024e67e96349ce0b993e571c17c37b030886e28e77bb30961619892d32dd083a`.
The observer, source manifest and catalogue pins are unchanged.

The contrasts use four of the 448 candidates: `detonateDeadCorpseLife` (`count`,
row 3), `conditionMoving` (`check`, row 6), `plagueBearerState` (`list`, row 155),
and `windDancerStacks` (`countAllowZero`, row 253). Original05 supplies neither
Input nor Placeholder for these names. Its controls still display fallback
values 0, false, `INC`, and 0, while the corresponding Config records are absent.

| Added source values | Independently expected Config records |
| --- | --- |
| Moving false, corpse count 0, Wind Dancer 0, list `INC` | Incubating flag and Wind Dancer BASE 0; no Moving or corpse record |
| Moving true, corpse count 17, Wind Dancer 3, list `INF` | Corpse SkillData LIST 17, Moving flag, Infecting flag, Wind Dancer BASE 3, in catalogue order |
| Numeric Placeholders: corpse 11 and Wind Dancer 7; other two names absent | Corpse SkillData LIST 11 and Wind Dancer BASE 7 |
| The same Placeholders plus authored Input 0 for both numeric names | Corpse falls back to 11; `countAllowZero` preserves authored Wind Dancer 0 |

The XML entries deliberately use the opposite order from the catalogue. Tests
check complete typed records, multiplicity and order, all remaining Player and
Enemy Config records, exact raw/load/saved lanes, and delivery through the
existing MAIN and CALCS observations. An authored first list choice emits a
record that the identical displayed fallback does not. These are actual original
loader/dispatcher contrasts; no Lua callback is replaced or interpreted in Rust.
There is no callback-invocation trace, proof for every callback body, native
assignment, or new permission to close the 448-row family from raw absence alone.

An ordinary Rust Authoring release test authenticates this packet without Lua
or a local PoB checkout. It checks complete archives, all function spans, exact
row/site identities, the unchanged Original05 source join and current Pending
obligations. Corrupting a row, reader, callback, source or admission marker cannot
silently change the evidence boundary.

Set `POE_CONFIGURATION_INPUTS_SOURCE_OUT` to a fresh output directory, then run:

```text
cargo test --locked -p poe-optimizer-pob --test owned_configuration_inputs_source
cargo test --locked -p poe-optimizer-authoring --test release configuration_source_census
```

## Next publication boundary

The [missing-raw proof contract](../configuration-missing-raw/README.md) is
implemented. Production assignments still need reviewed semantics and complete
combined evidence commitments:

1. Bind fresh construction, ordered defaults, normal load/migration, callback
   dispatch and relevant writers/readers before admitting a shared absent-callback
   family. Raw-name absence alone is insufficient. Preserve repeated callback
   identities and excluded direct or migration consumers.
2. Account for installed defaults under actual owners. Actor conditions,
   parent-qualified skill usage, trigger/target relations and statistical analysis
   are different responsibilities. Unknown child applicability is not no child.
3. Finish the direct/computed families with exact keys, fallbacks and precedence.
   Ordinary equipment/passive legality survives an absent override switch.
4. Publish through the existing inventory transaction. Require every leaf,
   independent consumer, adapter receipt and remaining owner to be accounted for;
   the unchanged Original05 replay may retire only the intended Choice issue.

decisions. Statistical-mode findings do not authorize copying PoB modes into
native Actor assumptions or silently choosing new metrics.
The [installed-default review](installed-defaults.md) identifies eight Actor
assumption responsibilities, twelve parent-qualified or relational skill usage
intents, and four unresolved reference-analysis choices. The latter are included
in the existing Calcs ownership proposal; native metric definitions remain the
first choice for expressing their eventual statistical meaning.
