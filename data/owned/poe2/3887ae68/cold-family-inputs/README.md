# Ordinary cold-resistance raw family

This successor repairs fixed cold-resistance import and expands structural family membership
from one template to the complete finite catalog of 1,756 constructed bases. It uses the
existing owned extension and line-policy contracts; no Core field, evaluator opcode,
source interpreter or runtime callback is added.

## Publish and evidence

Apply after the 10,537-entry item-metadata successor:

```powershell
poe-optimizer extend-owned-recipe PRIOR --extension data/owned/poe2/3887ae68/cold-family-inputs/extension.json --items data/owned/poe2/3887ae68/cold-family-inputs/items.json --item-source data/owned/poe2/3887ae68/cold-family-inputs/item-source.json --output NEW
```

The extension adds canonical cold owner2542 to 1,755 existing template modifier memberships;
Sapphire Ring already has it. Every prior member, Partial closure/gap and unrelated schema
field stays exact. Registry IDs, slots, numerical programs and receivers are unchanged.
The generic publisher validates typed membership refinement and rebinds the package to the
new schema identity. It does not infer template membership from a source name.

`family.json` is authoring evidence: exact base-catalog hash/source pins, predecessor and
successor schema identities, canonical owner and the complete finite template/header join.
The Rust authoring and regression checks verify this bijection against the actual policies.
The generic publication command consumes the authored extension, not this companion receipt;
its presence alone does not authenticate source extraction or justify semantic coverage.
The optional PoB test executes the pinned ordinary parser across the constructed catalog.
No wildcard permission is granted to future templates or unrelated modifier families.

## Fresh source values

The old `fixed-cold` recipe emitted early owner09d6 with one nominal roll. The successor
replaces it with an explicit `+` literal and unsigned decimal capture; `fixed-minus-cold`
uses a `-` literal and negates its unsigned decimal capture. Both emit canonical2542.
Bare unsigned text, scientific spelling and malformed doubled signs remain unrecognized.
The existing range grammars are unchanged. This is fresh text conversion, not copying an
old nominal value or changing an old definition's meaning.

The raw signed amount2543 uses exact decimal handling, without the range-only decimal
transport or numerical rounding. The other22 inputs are the20 source-attributed property
Booleans, explicit ordinary-line unscalable=false and corrupted-base factor1. A plain
admitted untagged line supplies all20false; properties are not guessed from English names.
Unknown/unconsumed properties and flags, corruptedRange, rune, crafted, variant and
combined-line controls retain their existing blockers. Recognized fractured/desecrated
flags are still unconsumed by this family and cannot be silently discarded.

Internal precision, corruption/magnitude scaling, source formatting, cached partial results
and later eligibility are separate stages. Both fixed recipes have Unresolved source roles.
Direct text conversion describes their raw values, but source-attributed admission and
subsequent member indices remain blocked pending a context-conditioned proof:

- Source formats `-0` and small negative fractions as unsigned zero, retaining a partial
  ColdResist row and `extra` diagnostic. A following condition can become the same member.
- Huge finite integers format in scientific notation and can follow the same retry path.
  The shared source adapter now also withholds membership proof for ValueOutsideSchema.
- An in-range leading-dot decimal with matching catalyst scaling can produce malformed
  scientific text. Restricting only the numerical value does not prove source membership.
- Negative catalyst quality can turn an integer `+10` into malformed `+-10`; restricting
  the capture to Integer would still not justify an unconditional SingleModifier role.

The next source-admission contract must bind reviewed lexical and contextual prerequisites,
including magnitude inputs, before proving a physical line is an independent member. This
belongs in the offline/import boundary, not a PoB formatting interpreter in the evaluator.
Canonical parameter membership stays Partial. Drafts retain unresolved roll, modifier-order
and whole-item collections; the three original membership failures are repaired but their
source-attributed admission remains withheld. All 22 original fixed-cold lines stay blocked.

## Separate contracts

Structural family membership says a known template can carry this raw modifier record.
It does not say every base can naturally roll cold resistance, nor that it contributes to
an equipped actor. Affix generation/crafting legality, source eligibility, flask/charm
activation, ordered transforms and receiver coverage need their own injected contracts.
New non-weapon templates do not acquire fabricated catalyst or quality values. Existing
missing producers stay unavailable.

Old09d6/09d7 and their direct contribution program retain their original identities for
existing consumers and immutable predecessor packages. The successor importer stops
emitting them for fixed cold text; it does not broadly enable that early direct program.
No existing Python utility or test is converted by this checkpoint.
