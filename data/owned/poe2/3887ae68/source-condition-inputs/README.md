# Conditional source membership

This source-only successor activates a reviewed fixed positive cold-resistance grammar
under explicit prerequisites. Apply it after the cold-family successor. Schema, item-line
recipes, numerical programs, registry IDs, query rows and receivers stay byte-identical.

```powershell
poe-optimizer extend-owned-recipe PRIOR --extension data/owned/poe2/3887ae68/source-condition-inputs/extension.json --items PRIOR/items.json --item-source data/owned/poe2/3887ae68/source-condition-inputs/item-source.json --output NEW
```

The fixed-cold role stays Unresolved in the fallback table. Version 6 supplies one all-of
conditional proof, bound to the exact item-line policy and thereby its schema:

1. NoSourceTags: the original physical line has no brace/control tokens. Stripping tags
   or projecting an empty property map cannot satisfy this prerequisite.
2. NoGeneratedBuffMembers: exactly one base was recognized in its source position, with
   reviewed absence of generated prefix members. Unknown/generated prefixes stay blocked.
3. UnsignedIntegerCapture: capture `amount` is entirely ASCII digits with raw inclusive
   value 0..1,000,000. Signs, decimals and scientific spelling fail even when the decoded
   numerical value would be in range. Leading zeros are permitted; the rule's '+' is literal.

All existing source-control, previous-line combination, header, property, range and template
checks remain. A failed condition adds an explicit per-line blocker and cannot release the
following physical line through an older raw-text recipe. Minus, tagged and fractional cold
values remain representable by the direct raw converter, but this proof does not admit them.

The pinned source begins these ordinary lines with empty modTags. That empty set forces the
initial catalyst scalar to 1 without consulting catalyst quality, including negative values.
Advanced copy sections can inject tags into later untagged-looking lines, so the existing
unsupported-source-control gate remains necessary. A supplied Sapphire Charm +25% cold line
can duplicate a generated buff and be skipped, which is why the prefix prerequisite applies
to fixed lines as well as ranges. No item-name or skill-name switch exists in the Rust guard.

Reference validation executes authentic ParseRaw, including its nested BuildModList. It
records the initial parser/formatter separately from later assembly. Complete initial
parsing and a stable member boundary do not establish final numeric value, equipment
activation, crafting legality or whole-build parity. Canonical roll membership remains
Partial, and numerical eligibility, missing producers and complete-item gates remain open.

See [the contract](../../../../../docs/owned-source-conditions.md). The first real consumer
is three already source-compatible records on Frayed Shoes, Iron Ring and Gold Ring; the
conditions apply to the reviewed grammar and base catalog, not a build or item allowlist.
