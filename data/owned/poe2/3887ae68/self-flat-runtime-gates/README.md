# Selected self-flat runtime gates

This is offline source evidence for unchanged supplied Original05: tree 3,
equipment 2, skills 4, configuration 1, main group 3. It authorizes no native
coverage, closes no saved-input obligation, and is not whole-build parity.

## Acquisition and determinism

Exactly six fresh original PoB loads were executed. Each of two independent
processes made two instrumented loads with JIT disabled and one uninstrumented
control. The controls had JIT disabled and enabled respectively. Hooks observed
the pinned original functions and caller locals; no calculation method was
replaced. Supplemental original Flag/Tabulate probes checked that their stores,
configuration and Actor outputs were unchanged. These probes are distinguished
from actually executed original consumers.

All six complete scalar output snapshots agree exactly. The initial strict
JIT-off observation comparison failed: 46 lists permuted Pain Offering's
different-stat records, Speed INC 30 and Damage INC 62. These are 10 group
deliveries, 18 Player buff visits and 18 Player skill buff inventories. All
record fields, occurrence counts, contexts and other observations agree. The
JIT-on pair agreed without that adjustment. No load was retried: the remaining
three JIT-on loads were completed using the same compiled child after inspecting
and preserving the first failure.

The offline comparison permits stable stat-name bucketing only at the three
inventory paths listed in `report.json`. It preserves full records, duplicate
counts and order within each stat. Every other observation field and every
numeric output is compared exactly. Raw arrays remain in their observed order.
This is an inventory comparison, not a native arithmetic ordering rule. It
does not permit reassociating floating-point reductions or reordering same-stat
contributions. Wall-clock duration is diagnostic and is excluded from equality.

The six `*-raw.json` files are the exact acquired bytes. `report.json` binds
their hashes, pinned original source manifest, unchanged XML and exact archived
driver, observer, shared helper and bootstrap bytes. Archived files are never
executed by ordinary tests. Current maintained Rust tests verify the proof and
mutations; the ignored current source target is the optional acquisition entry.
The exact original `acquisition-jit-on.json` also remains retained: its witness
hashes must match those archived bytes and its state must match the corresponding
raw run. The later proof author does not silently substitute current code for
the acquisition witness.

## What was actually observed

- The selected Sniper Basic Attack reached the parent-weapon condition in MAIN
  and CALCULATOR. Four line visits correspond to two actual original Flag calls;
  a Lua line visit is not counted as a separate consumer. The Player and main
  hand item were present. Raw and eligible `GainMainHandDmgFromParent` records
  were empty, the original supplemental Flag result was absent, and the branch
  was never entered.
- Eighteen Sniper preparation visits reached the Hollow Palm condition. Its
  Actor condition was absent and the original condition short-circuited: zero
  original Facebreaker/Hollow Palm Flag calls occurred. The separate probes
  retained their exact Action configuration, empty raw/eligible records and
  absent original Flag results. Absent is not serialized as false.
- Eighteen original Player `ExtraAura` List consumers returned empty lists with
  empty raw candidates. No Player or supplied-child `ExtraAuraEffect` consumer
  executed. Complete traversed buff inventories contain only Player Pain
  Offering Buff, Player Frost Bomb Debuff and supplied Reaver Rage Buff; none
  is an Aura. The unconditional `ExtraAura` query is therefore checked separately
  from Aura skill traversal.
- The traversal retains 288 Player visits and 432 child visits over the original
  load's calculation passes, including 16 distinct child effect IDs and six
  profiles. The Reaver Rage buff was visited 18 times with `skillData.enable`
  absent. No child buff merge executed. Twenty-eight actual group deliveries
  contain only Pain Offering to the selected minion or Frost Bomb to the enemy.
- Final MAIN/CALCS stores retain all eight supplied Actor occurrences and the
  selected raw name inventory. Player records are the 30 existing
  `MinionModifier` wrappers; the corresponding named raw lists on supplied
  Actors are empty. These observations are bounded to the explicitly captured
  names and stores, not a claim that every possible modifier store was empty.

## Diagnostic limitation and maintained observer

The archived observer read traversal flags from the absent convenience field
`activeSkill.skillFlags`. Its empty `flags` objects are unavailable diagnostics,
not evidence that effective flags were false. The current maintained observer
reads the mode-specific `activeEffect.statSet` or `statSetCalcs` flags instead.
That correction was syntax checked; it was not exercised in these six retained
loads and its values are not backfilled. The no-Aura statement above follows
from the complete buff inventories and actual consumer hooks. Any other proof
requiring effective traversal flags remains open. At Hollow Palm preparation
`env.minion` is not yet selected; exact identity there follows the observed
profile, child effect, supplying occurrence and summoner ownership, not a false
claim that `actor_is_selected_minion` was already true.

## Remaining selected-flat work

The selected recipe audit and these runtime observations now give bounded
source evidence for the previously unobserved parent-weapon, Hollow Palm,
Player ExtraAura and supplied-child Buff/Aura routes. They do not install a
native selected-source producer inventory. The next native step is to bind
the exact selected item/tree/configuration/skill source occurrences to reviewed
flat-damage dispositions and compile their completeness through the existing
contribution graph. Configuration and external-input obligations still require
explicit checked accounting. A zero observed total cannot retire those inputs.

Only then can the selected unchanged attack publish a checked empty or populated
self-flat contribution domain and its damage endpoints. Other configurations,
Party input, changed equipment, changed supports or Action-sensitive supplier
conditions require their own admitted rules and completeness checks. No new
general native transport API is implied by these runtime observations.
