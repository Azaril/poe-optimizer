# Local modifier scalar and contribution inputs

This append-only owned extension adds25 ordinary programs to nine existing
canonical local Modifier definitions. It allocates no IDs, parameters, tables or
receivers and leaves all existing schema/rule coverage unchanged. Apply it after
the canonical admission revision2 and weapon-catalyst input stages, using an
explicit validated predecessor:

```powershell
poe-optimizer extend-owned-recipe PRIOR --extension data/owned/poe2/3887ae68/local-scaling-inputs/extension.json --output NEW
```

The nine families receive the reviewed canonical cold modifier's catalyst-scalar
program with only the property parameter addresses replaced by their semantic
counterparts. They read exact EquipmentUse catalyst selection/amount stats
`0a19`/`0a1a` and emit Modifier scalar `0a1b`. All13 selector options, the four-way
Defence property test and the explicit unscalable branch retain the same owned
expressions. Missing inputs remain unresolved; no runtime default or source
lookup is introduced. The copied ordered-magnitude program reads the complete
ordered transform channel with initial `0a1b` and emits Modifier stat `253d`.
An empty transform list requires independent completeness proof.

Seven additional programs consume canonical effective stats and contribute to
existing EquipmentUse receiver channels:

| Canonical owner | Effective input | Contribution |
| --- | --- | --- |
| Physical increase `2570` | Percentage `253e` | Increase physical minimum `242d` and maximum `242e` |
| Attack-speed increase `258d` | Percentage `253e` | Increase attack rate `242b` |
| Critical increase `25aa` | Percentage `253e` | Increase critical chance `242c` |
| Flat critical `25c7` | Percentage `253e` | Add critical chance `242c` |
| Flat physical `25e3` | Minimum `253f`, maximum `2540` | Add physical minimum `242d`, maximum `242e` |

IDs abbreviate `def.000000000000` in the package namespace. Every program uses
EquipmentUse context, reads its exact Modifier occurrence, and contributes to
that receiving EquipmentUse. It never substitutes a nominal roll for an absent
effective value. Signed qualifier results are already resolved by the canonical
value stage; the contribution layer preserves that sign.

Cold, Fire, Lightning and Chaos flat families gain both scalar stages but no
weapon contribution yet. Their raw profile channels are existing baseline
producers. Eight distinct assembled channels and reviewed receivers are needed;
elemental increase and rounding differ from the unrounded Chaos prefix. Current
rate/critical outputs remain pre-override and physical outputs remain before
positive-pair presence and later WeaponData overrides. No action route or metric
is added.

The Rust production CLI helper loads the real predecessor, validates publication
and immutability, and compiles all authored rules. Component tests cover13
catalyst selections, Defence alternatives, nonmatching/None/unscalable lazy
branches, exact missing facts, canonical value-to-contribution-to-receiver
arithmetic, negative qualifiers, independent worker scratch and changed inputs.
The tests explicitly supply facts and complete reduction values at component
boundaries; they do not prove build occurrence binding, source lifecycle or
incoming membership. Existing generic engine tests cover those separate seams.

Imported canonical rolls remain Partial and cannot authorize final effective
values. Source cache history, scaling eligibility, corruption/range handling,
modifier order, contribution membership, rune reconstruction and action
compatibility remain unresolved where previously unresolved. Adding scalar and
consumer programs closes none of these gaps. The original110 query rows and0/5
complete-build status are preserved. Runtime data stays injected; optional PoB
source/parity tools remain outside this native component.
