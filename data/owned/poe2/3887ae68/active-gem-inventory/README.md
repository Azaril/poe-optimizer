# Active physical Gem inventory: Pain Offering

This publication classifies the saved physical inputs of a single-primary active
Gem. It reuses the existing level, quality, corruption and Boolean usage recipes.
It adds no definition, scalar value, numerical rule, evaluator operation or
source-language execution to the native path.

`inventory.json` names the reviewed physical identity, its two existing corruption
slots and its existing primary-effect usage policy. The catalog proves that this
Gem has exactly one constructed effect and no additional effects or stat sets.
The publication retains every previous support inventory under the shared V2
physical inventory contract. `authoring.json` binds the exact predecessor,
catalog, source manifest and authored rows.

| Saved field family | Disposition |
| --- | --- |
| Physical identities, level, quality, corruption | Existing exact mapping and typed physical input conversion |
| Gem/group enabled state and source | Existing physical SkillUse activation and admitted source scope |
| `enableGlobal1` | Existing typed preference on the exact primary generated Skill, in the containing preset |
| Count, global settings and group reporting | Explicitly incomplete preset usage inventory; no implicit count, population, reservation or reporting conversion |
| Labels and saved main/calculation selection | Preserved source attribution and unchanged original query selection |
| Additional attributes, child maps or unsupported group overrides | The finite physical inventory proof does not apply; known scalar values survive with Pending coverage |

The proof requires an actually attached, complete Boolean preference and a
**Pending** containing-preset usage inventory. A matching catalog row or a usage
policy declaration alone cannot complete a physical parameter list. This makes
the distinction explicit: the two intrinsic parameter assignments can be complete
while count/reporting and other usage semantics remain unresolved elsewhere.

All original source bytes, queries, static definition/rule coverage and unresolved
usage/scenario/actor/action obligations survive. This publication does not claim
native build parity or complete usage semantics. The optional full-source witness
checks the count, global-switch and reporting consumers independently in both JIT
modes. Normal native tests need no PoB checkout.

Validation completed on all five unchanged originals. Three saved Offering
occurrences now have complete physical parameter lists; the selected Sniper
request retains eighteen unresolved issues, down from nineteen. All 110 queries
and every other selected obligation survive. The source witness passes eleven
isolated controls plus fresh-repeat and warm-restoration checks in each JIT mode;
its full 3,055,579-byte observations match exactly and are authenticated by the
authoring receipt. Complete native builds remain zero of five.
