# Ordered modifier scalar inputs

This extension appends one Modifier-scoped factor stat and two consumer programs to the
actor-baseline successor. It upgrades the explicit operation contract to v10; older
programs, declarations, query rows and Partial gaps are retained. The programs start
from the existing catalyst scalar and consume the ordered modifier-transform channel.
They do not assume an empty sequence merely because no transform was imported.

Use `extend-owned-recipe PRIOR --extension data/owned/poe2/3887ae68/modifier-transform-inputs/extension.json --output NEW`.
`PRIOR` must be the checked actor-baseline successor with 9,532 registry entries. The
shared publisher rebinds the existing import/tree artifacts without overwriting paths.

Each transform producer has an explicit step number and typed finite target definitions.
Recipient eligibility is an ordinary Boolean Modifier stat; its rules can use the existing
expression language. Binding uses the same receiving equipment use and backing item,
orders producers by `ItemRecord.modifier_order`, then orders steps within each producer.
Unknown predicates, activation, initial values or contributor membership do not become
identity factors. An explicitly complete empty sequence preserves its initial scalar.

These outputs remain intermediate scalars. Actual source transform producers, complete
membership/order, source-value encoding, corrupted-base and component formatting still
need conversion. Fixed-source reparsing history remains an import compatibility question;
it is not native mutable state. Native final resistance/weapon contributions must consume
separately proven effective values, not these scalars or nominal rolls directly.
