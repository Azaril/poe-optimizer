# Cold modifier source category

This prerequisite adds one required Option parameter, `316d`, to cold modifier
`2542`. Its values are the existing Explicit `30e2`, Implicit `30e3`, and Enchant
`30e4` options. The existing 23 parameters and four numerical programs are
preserved. No final resistance contribution or metric binding is added.

All four cold item-line recipes now require the existing
`modifier-source-category` context input. The source policy supplies that input
only for an exact member in a fully Proven item layout. A Pending layout can
retain a recognized candidate and useful diagnostic positions without proving
its category; such a candidate no longer creates a canonical cold modifier.

The checked recipe extension first appends the slot while retaining the prior
Partial parameter declaration. A checked full endpoint installs the required
roll and its exact dependent bindings together. A checked release revision then
marks the 24-parameter inventory Complete. The cold owner, numerical coverage,
item-template memberships, routing and final outputs retain their existing
gaps. The authored source conditions are unchanged.

## Admission boundary

`fixed-cold` still requires a literal plus sign, unsigned integer amount from 0
through 1,000,000, no source annotation tags, and the reviewed absence of generated
buff members. `ranged-plus-cold` retains its existing positive integer endpoint,
identity initial scaling, and generated-member guards. Range interpolation and
the existing numerical programs are unchanged.

The complete-source Sapphire witness observes fixed `+0%` as a complete active
ColdResist BASE 0 record. Negative zero, bare positive text and a zero range can
leave a partial parser record with unconsumed text and no active cold record;
those are not admission evidence. `fixed-minus-cold` and `ranged-bare-cold` retain
their unproved source roles. The new required category does not make them
admissible.

The 20 property inputs continue to reflect parsed source tags rather than the
English modifier name or an affix catalogue. Recognized fractured or desecrated
flags have no corresponding cold parameter and are rejected as unconsumed
properties. Unknown flags/tags, unsupported variant/rune structure and an
unproved preceding member cannot silently become a Complete cold occurrence.
Numerical scaling and source-encoding gaps remain separate from this finite
parameter inventory.

## Reproduction and preservation

`tests/support/owned_cold_category_inputs.rs` reads these typed assets and accepts
only the exact Solar input recorded in `authoring.json`. It checks the four
complete prior recipes and two source-condition rows against their snapshots,
uses the registry's checked append, and restores the entire prior endpoint to
prove the allowed change set. All prior numeric programs, source facts, query
sets and provenance remain intact. Its two new provenance rows record the
authored addition and the explicit parameter-inventory revision.

The Sapphire publication target consumes this prerequisite before its independent
ring correction and four-slot append:

```powershell
$env:POE_OPTIMIZER_TEST_SAPPHIRE_INPUTS_PRIOR = 'runs/owned-solar-item-inputs-01/package'
$env:POE_OPTIMIZER_TEST_SAPPHIRE_INPUTS_OUTPUT = 'runs/owned-sapphire-item-inputs-01'
cargo test --locked --test owned_sapphire_item_inputs -- --include-ignored
```

Use a fresh output directory. The real test checks full endpoint restoration,
publication/rebuild bytes, all five original imports and saved selections, all
110 queries byte-for-byte, and the predecessor inventory. Source verification is
the optional `owned_sapphire_item_inputs` target in `poe-optimizer-pob`, pinned in
`authoring.json`; it executes the complete source methods in both JIT modes.

The recorded predecessor census contains 18 canonical cold occurrences: three
have Proven layouts and can receive the category; 15 have Pending layouts and
must be withheld, including eight selected occurrences across originals 01–04.
The three retained occurrences are the inactive original-02 source rows 501/506
and original-05 Sapphire row 587. The final normalization run is authoritative
for these counts. Removal of a withdrawn occurrence's old roll issue is not a
numerical or completeness improvement. No original build is declared complete.
