# Explicit empty Spec socket membership

This opt-in source grammar closes an allocation preset's equipment membership
only when its canonical saved Spec has one explicit, plain, empty `Sockets`
container and all relevant source shape checks pass. The policy has no build
identifiers, selected Spec numbers, game definitions, or implicit empty defaults.
Occupied siblings, omission, duplicate containers, namespaces, nesting and
unknown children remain Pending. Other allocation, access, point-budget and item
facts remain separate.

The pinned source path is full `TreeTab.Load`, fresh `PassiveSpec` construction,
complete `PassiveSpec.Load`, and `PostLoad`. `PassiveSpec.Load` alone does not
clear an existing jewels table, so a reused instance is not evidence that an
empty container creates an empty inventory. The optional Rust source witness
uses complete authenticated methods and original saved selections in both JIT
modes. `authoring.json` binds the exact predecessor and source module pins.
The complete loaded original Spec3 has zero positive equipped members and 19
numeric-zero placeholders in its source table; Specs5/6 each have three positive
members. The proof concerns equipment membership, not an empty Lua table.

The Rust CLI regression preserves all five original builds and all 110 queries
byte-for-byte, compares every unrelated draft field and selected issue, retains local instance
IDs, allocator watermarks and provenance, and verifies byte-identical rebuild.
Fresh CLI projects have separate lineages; the comparison canonicalizes only
those lineage values. Original05's selected Spec3
is the positive case; its occupied Specs5/6 are independent negative controls.
