# Intrinsic item-template support domains

This tranche adds `AuthoredAssignmentsOnly` support-source domains to four
existing ItemTemplates: Ashen Staff (`1d75`), Fine Belt (`1e84`), Rope Cuffs
(`2007`) and Tattered Robe (`238c`). It allocates no identifiers or programs.
It does not certify their rolled modifiers, numerical owners, generated
descendants or complete build coverage.

The maintained Authoring release tests reuse the complete
[structural source proof](../item-structural-inventories/README.md), without its
historical migration/publisher. `evidence.json` pins those existing records,
three additional already retained constructor files, seventeen source spans and
all six direct record-creation sites in the item constructors. Full upstream
files remain bound to source revision `3887ae68a6a6b8bb7b41d1b61998f1aa184201e4`
through the existing manifest. No source code executes in the native evaluator.

Quality, movement and ArmourData records remain numerical outputs. The two
Grand Spectrum constructor sites belong to the Jewel branch, which none of
these four base records admits. Implicit, explicit, enchantment, rune,
class-requirement and buff modifier records keep their separate suppliers.
Positive ExtraSupport and LinkedSupport factories and their consumers remain
in the proof, so the template classification cannot erase external supports.
PoB's cosmetic-name ArmourData branches are retained as source observations;
this tranche neither adopts their numerical behavior nor declares them absent.

Ashen Staff's Firebolt stays on `Modifier31c6 → Grant31c8 → SkillGrant31c9 →
Skill0134`. Its variable inputs and Partial output coverage are preserved.
The unchanged Original05 selection has nine equipment uses of eight physical
records, including two separate uses of ring 26. The four reviewed templates
each have one selected use. These are test provenance checks, never production
dispatch on item names or build identities.

The four declarations live in the existing program-free metadata of
[`migration-source`](../migration-source/release.kdl). Ordinary release assembly,
exact corpus inversion, source mutations, supplying-owner checks and all five
original imports remain the validation gates. The current allocation predecessor
is unchanged; build the source through the atomic authoring checkpoint workflow.
Complete native builds remain **0/5**.
