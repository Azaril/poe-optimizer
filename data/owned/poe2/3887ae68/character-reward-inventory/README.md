# Character-only reward inventory

This optional source profile proves an empty **character-owned** reward selection
inventory for the reviewed fresh Build and modern Spec loader domain. It preserves
the separate Config reward selections and progression budgets. It adds no
definitions, modifier programs, numerical outputs, or runtime coverage.

The policy binds the exact mapping source, source target version `0_1`, and tree
version `0_5`. Those versions identify different loader boundaries. Unknown,
legacy, namespaced, duplicate, automatic-level, or unreviewed source shapes keep
their previous Pending result. The full Build/Tree frame must pass before any Spec
receives authority; complete known members alone do not prove an inventory.

`authoring.json` binds the exact default-encounter predecessor, pinned source
files, and all five query files. The dedicated complete-source witness passes in
both JIT modes with identical evidence: sixteen attempts per mode, fourteen
complete loads and two expected exits into target-version conversion. It observes
the five originals and eleven controls, including actual Config reward changes,
Spec selection, cached outputs, BeastCompanion and TimelessData state. Its twelve
non-Config quest records contribute progression budgets, not selected character
rewards. The staging helper requires the recorded passing source validation.

Publication changes only the optional normalization policy, its version, the
checked tree binding, and one provenance row. The helper removes precisely these
changes and requires equality with the entire predecessor. Registry, definitions,
rules, mappings, reward policy, item policies, tree content, and all 110 queries
remain unchanged.

The real CLI regression independently counts source Specs, proves each retired
issue belongs to its exact character preset, preserves all draft IDs and allocator
watermarks, and compares every remaining source link. Historical fallback links to
the same retired issue are removed; no other source evidence is discarded. It
also checks saved selections and all remaining selected issues, preserves all 81
Config reward records, rebuilds the published package byte-for-byte, rejects a
stale source commitment, and exercises positive and excluded source mutations.
Expected totals are assertions to be measured by that run, not source evidence.

The first real publication passes: all sixteen character inventories complete,
with selected issue counts **123 / 124 / 116 / 153 / 20** and all eighty-one Config
rewards preserved. Both CLI tests and all sixteen source probes pass. The endpoint
is `runs/owned-character-reward-inventory-01/package`, input
`ad6a01300b11230fb452b52fe36c04343ac1daf9109a68a5e43a11f986bd32ef`.
Native completion remains **0/5**. This checkpoint also passes 207 focused Import
and transition tests, strict workspace Clippy, both WASM configurations, formatting
and dependency-boundary checks. Full workspace runtime tests were not repeated.

Run the lightweight authoring check with:

```powershell
cargo test --locked -p poe-optimizer-cli --test owned_character_reward_inventory
```

After the complete-source witness has passed, run the real publication with an
explicit predecessor and a fresh output directory:

```powershell
$env:POE_OPTIMIZER_TEST_CHARACTER_REWARD_INVENTORY_PRIOR = 'runs/owned-default-encounter-02/package'
$env:POE_OPTIMIZER_TEST_CHARACTER_REWARD_INVENTORY_OUTPUT = 'runs/owned-character-reward-inventory-01'
cargo test --locked -p poe-optimizer-cli --test owned_character_reward_inventory -- --include-ignored --nocapture
```

The resulting `validation.json` records the measured completions, retained Config
rewards, selected issue counts, and probe count. Native calculations remain
`not_run`; this profile does not complete any original build.
