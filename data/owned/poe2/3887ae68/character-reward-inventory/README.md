# Character-only reward inventory

This optional source profile proves an empty **character-owned** reward selection
inventory for the reviewed fresh Build and modern Spec loader domain. Config
reward selections and progression budgets remain independent. The profile adds
no definitions, modifier programs, numerical outputs or runtime coverage.

The policy binds the exact mapping source, source target version `0_1`, and tree
version `0_5`. Those versions identify different loader boundaries. Unknown,
legacy, namespaced, duplicate, automatic-level or unreviewed source shapes keep
their previous Pending result. The full Build/Tree frame must pass before any
Spec receives reward authority; known members alone do not prove an inventory.

`policy.json` remains the source-bound policy used by the maintained release.
`authoring.json` records the historical default-encounter predecessor, pinned
source files and query commitments. Its old release identities and selected
issue counts describe that publication, not the current release.

The retained complete-source witness, `owned_character_reward_source`, observes
five originals and eleven controls in both JIT modes. Its sixteen attempts include
fourteen complete loads and two expected target-version conversion exits. It
checks actual Config reward changes, Spec selection, cached outputs,
BeastCompanion and TimelessData state. The twelve non-Config quest records in
that witness contribute progression budgets rather than selected character
rewards. This evidence remains independent of the ordinary native tests.

The maintained Authoring `release::character_reward_inventory` tests compare the
checked current release with a checked reconstruction in which this optional
policy is absent. They bind every Character preset to its exact originating Spec;
additional Build and Tree provenance projections do not create duplicate Spec
owners. Across all five originals they preserve all sixteen Character identities,
all current Config reward records, every other draft field, allocators, saved
selection, native queries and unresolved selected obligations. Only the exact
empty reward inventories and their issue links retire.

Build-header attribution and default Timeless search-preference accounting. The
maintained inverse checks those two source-only changes explicitly and separately
from reward completion. Thirteen of sixteen real-source contrasts reach the full
