# Contribution producer address cutover

The current member format names a typed `producer` and optional numeric `order`.
Ordinary effects retain their exact owner, program, effect and origin inside
`program_effect`. `application_group` instead names the stacking family, modifier
and complete application/effect declaration set. It requires operations V25.
There is no parser alias for the prior development representation.

`rebuild.json` records the mechanical re-expression of the existing canonical
package's 2,017 ordinary members and the seven maintained data files containing
members. The eighth artifact changes only a reference byte pin. Numeric rules,
membership, ordering and coverage are unchanged. Five authoring commitments were
recalculated in their existing serialization domains; the receipt preserves their
old and new values. Source observations and their independent reports are retained.

The rebuild starts from commit `d1dd93c` and the checked flat-Life-routing input
named in the receipt. Historical package bytes remain historical evidence; they
are not accepted by the current runtime. The rebuilt package still declares V24
because its members are ordinary effects. V25 is used by the new application-group
tests and will be adopted by the next real damage-consumer publication.

`owned_application_group_producers` checks byte pins automatically and verifies
the full five-build import/finalization corpus when both local packages are
provided. Fresh CLI imports intentionally mint different project lineages. The
comparison authenticates each draft digest, then rebases only those lineages and
their bound digests; every other draft, sidecar and finalization field must agree.
The native Engine application tests validate group membership,
stacking, unknowns, exact recipients, ordering, stages, cycles and worker reuse.
Neither this format change nor those finite tests completes a real build.
