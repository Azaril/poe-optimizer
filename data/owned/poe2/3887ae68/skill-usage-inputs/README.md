# Skill usage inputs: Pain Offering activation

This family connects an explicit saved usage Boolean to the existing native Pain
Offering application. It allocates only UsagePolicy `3259` and its required
Boolean ParameterSlot `325a`. One ordinary Skill-context rule derives the existing
effect-active stat `3227` on the exact generated Skill occurrence. The supply
`3221`, entering grant `3222`, Offering arithmetic, recipient selector and
per-recipient maximum stacking remain in the existing `pain-offering` family.

`extension.json` contains the two schema allocations and one complete usage owner.
The owner is complete for this Boolean rule; existing game owners and application
membership remain Partial. `native-inputs.json` names the typed bindings used by
native component tests. Neither artifact interprets source fields at runtime.

`policy.json` is a **predecessor-bound authoring template**, not a ready-to-load
published normalization policy. `authoring.json` binds it to the exact preceding
release, definitions, registry and roles. Publication checks those commitments,
applies the checked two-ID extension, then deliberately rebinds the policy to the
successor definitions, roles and scalar-input commitment. The source catalog
commitment stays unchanged. Existing normalization fields and unrelated bytes
must be carried forward, without inventing parameter-inventory completeness.

The source lane is finite and data defined: the exact physical Pain Offering
identity and primary supply, a childless set of reviewed attributes, count `1`
or `3`, and explicit Boolean text `true` or `false`. Only `enableGlobal1` supplies
the primary effect activation. Numeric aliases and a missing value do not supply
a Boolean. Count is guarded evidence, not an imported population, statistic,
reservation or FullDPS multiplier. Unknown attributes, children or lexical values
remain unresolved; valid usage records still do not close the full preset usage
inventory or physical Gem parameter inventory.

The existing full-source witness loaded all five originals and isolated controls
in both JIT modes. `reference-vectors.json` is a compact projection of the original
Sniper build, Pain count-three control and global-false control from that measured
evidence, with the full bytes and source pins authenticated in `authoring.json`.
Count three retained the observed MAIN/CALCS actors' outputs. Global false removed
the Offering action and reduced the selected minion's observed speed and DPS.
Those source outputs establish the activation/count distinction; they are never
injected as native computed damage or presented as whole-build parity.

The dedicated Engine fixture replaces the old test-only activation choice with
this published rule and composes SkillPreset preferences plus whole-record
scenario overrides through Core's normal `compose_request`. It retains explicit
finite boundaries for final level/quality and source/recipient scaling. Tests
exercise active, inactive and absent usage, distinct copies and recipients,
maximum stacking, required-input gates, Partial membership, scratch reuse and
Rayon isolation. An optional test authenticates the compact observations against
the complete local witness; ordinary tests need no PoB checkout or ignored run
package.

Final level/quality production, supporting gems, scaling producer coverage,
complete physical inputs, remaining count/reporting/action semantics, other
recipients and speed effects are still separate work. This family does not
complete any original build or weaken existing required-input readiness.
