# Selected physical hit endpoints

This packet advances the exact intrinsic Basic Action from its physical base
range to its rounded physical hit range before critical multipliers and enemy
mitigation. It uses the normal owned rule package, contribution queries and
stage graph. It adds no evaluator, source-language execution or complete-build
coverage.

The Action reads its own base endpoints and increased-damage subtotal. Its
exact supplying Actor contributes quality, ordered unconditional MORE factors,
and two semantic Boolean conditions. Intimidated applies one reduced-damage
penalty regardless of how many sources provide it. Debilitated is multiplied
before quality and the remaining MORE factors; that bucket is rounded once.
The final damage range is rounded after all these factors.

The source comparison is deliberately finite. The selected source closure has
identity conversion, no gain as physical, no physical-type or endpoint-specific
scaling, no damage suppression and no provider of either new condition. Complete
raw records, including inactive and zero records, and complete archived source
bodies establish this domain. Potential providers are checked independently
from their observed result. Random elemental gain is a later damage component;
its source factory cannot change this physical range within the admitted
conversion domain.

The native Boolean queries are complete and empty only for that checked source
closure. A newly introduced provider must be explicitly accounted for in the
query; false, inactive and unselected writers do not evade this requirement.
Synthetic positive-condition tests exercise the reusable native mechanics and
are not evidence of a newly imported game source.

The retained full source report provides actual returned damage values. Those
values are test evidence only and never become runtime operands. Source-specific
names, modifier-store ancestry and source body scans stay in offline validation.
All pre-existing Partial owner, query-registry and input boundaries remain.

Publication requires the `authoring.json` review gate and the native/CLI tests.
The gate does not promote any existing incomplete build coverage.
