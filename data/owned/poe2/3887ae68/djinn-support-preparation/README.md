# Djinn support preparation

`preparation.json` is a source-independent `SupportPreparationInput` for the ten
supports present in the witnessed Djinn contexts: Bidding II/III, Magnified Area
I/II, Muster, Frost Nexus, Prolonged Duration II, Hulking Minions, Kurgal's Leash
and Rapid Casting II. The existing Data constructor checks its exact schema and
rule identities. Its 34 concrete type symbols, ten effect symbols and eight
family symbols belong to this artifact; they allocate no registry IDs.

This is a standalone sidecar bound to the accepted Ice Nova intrinsic release
(`179b0cd3decbfc79bd0c52ae087597ae5e7a3fc008b35c2638519c5236cf2191`).
All 18 release files, 110 queries, build IDs and coverage declarations remain
unchanged. The release has no evaluation bundle. Publishing preparation inside a
release requires the existing complete set of evaluator artifacts; this sidecar
does not create empty stages, receiving rules or effective-input producers.

The source witness observes the original constructors and admission predicate in
both JIT modes: twelve cases, three lifecycle stages and 1,296 exact contexts.
The six independent support-disable controls preserve the other candidates and
their acceptance. Frost Nexus adds `CreatesGroundEffect` during preparation;
the other nine supports add no type. Positive type alternatives translate to
typed OR. Hulking Minions requires `Minion AND Persistent`; the source `AND`
operator does not enter the concrete type vocabulary. Rapid Casting II excludes
Instant, FixedCastTime or NoAttackOrCastTime. Other exclusions and every
plus-version link are absent, and each support has its reviewed family.

`bindings.json` records the authoring correspondence between source names and
owned symbols/Gems. `source-vectors.json` keeps all ten raw source definitions and one
48-context source snapshot as evidence, with initial inputs separate from
observed constructor/final types and admission. These source files and contexts
are not runtime inputs. Native comparisons use the independently authenticated
full witness, not the snapshot as expected results. `authoring.json` binds all
artifacts, the five original XMLs, source pins and both identical witness reports.

`tests/support/owned_djinn_support_preparation.rs` checks the authored files
without local runs for ordinary CI. Its optional `load` path additionally checks
the actual release and full source evidence before constructing the immutable
Data artifact. Existing Djinn Action and tree bindings supply exact target paths
in the native component proof.

Preparation definitions do not provide effective support level/quality or
numerical support delivery. Distinct candidate definitions can be selected with
unknown effective values; duplicate selection must retain the existing missing
input result. Additional unreviewed supports still produce a missing-definition
result. The six selected support-target obligations, origin/usage
inventories, incomplete owners/contributors and whole-build evaluation remain
open. No observed final level, type set, acceptance result or build identity is
hard-coded into the runtime preparation artifact.
