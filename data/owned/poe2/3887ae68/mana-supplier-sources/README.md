# Offline Mana supplier source review

This packet reviews suppliers of the five native Mana adjustment channels
`3357`–`335b` for the unchanged supplied Original05. It grants no native
coverage, installs no zero producer, closes no import obligation and does not
make final Mana or the complete build available. It is test/authoring evidence;
production evaluation never loads these archives.

The required source census includes Mana conversion to Energy Shield, Armour
and Evasion; direct `ExtraMana` and `ManaTotal`; and both `ConvertToMana` and
`GainAsMana` from Armour, Evasion, Energy Shield, Life and Ward. A zero-valued or
inactive source still requires review. In particular, the resource pass's
procedural zero `Conversion` records are real writes, not absence evidence.

## Concrete body exclusions

`initialization-bodies.json` retains the complete pinned `CalcSetup.lua`
`initModDB` body at lines 26–114 and the Player initialization/class block at
827–899. The former declares 84 literal writes; the latter declares 64 literal
writes plus the explicit `Str`, `Dex`, `Int` loop. Class fields supply values,
never arbitrary modifier names. Conditions and values do not change this
finite writer-name domain.

All 18 captured pre-configuration Player stores in each independent observation
contain exactly the corresponding 151 records across 136 names, preserving
duplicate counts. These are 16 MAIN visits, one CALCS visit and one CALCULATOR
visit. No reviewed Mana adjustment name occurs. The original class values also
match the three constructed attribute records. This excludes these two pinned
initialization bodies as adjustment suppliers. It does not exclude every later
calculation phase, every callback, or every source attached to that Actor.

The subsequent `configuration-bodies.json` review reuses the same acquisition
and the existing configuration-accounting source archive. It binds the full
663-entry catalogue to two constructions: 62 default and 63 saved callbacks in
their actual order. Complete bodies cover 45 literal-writer domains, the
selected `None` boss branch and two quest-parser entry bodies. The latter's
seventeen variables now reconcile in both constructions through the finite
reward witness and exact selected native rewards. Arbitrary quest text remains
outside this proof. Exact default construction, callback arguments,
append-only record changes and the empty custom-text path are checked.

`configuration-auxiliary-bodies.json` retains the original control methods
reached by those constructors; the reviewed notification branch cannot hide
an unexamined callback. `configuration-review.json` is reconstructed by
`owned_mana_configuration_sources` without executing Lua or historical Rust.
Missing/altered callbacks, defaults, source identities, nested zero suppliers,
prior-record rewrites and nonempty custom text are rejected. These are bounded
direct-writer exclusions, not proof of later direct configuration consumers,
general quest parsing, native completeness or saved-field accounting.

## Acquisition and determinism

The accepted source acquisition is `owned-mana-supplier-source-02`: four fresh
original PoB loads, two hooked with JIT disabled and two unhooked controls with
JIT disabled/enabled respectively. Original functions were observed without
replacement. All complete scalar snapshots match exactly. The first acquisition
is diagnostic only: its observer had missing socket-group context and repeated
partial routing-header captures; none of its reports supplies this packet.

The six exact raw/report files and the exact four acquisition witnesses are
retained as gzip archives. `source-comparison.json` pins them separately from
the subsequently maintained comparison driver. That accepted offline comparison
allows only the reviewed source-inventory permutations: different stat names,
distinct constructed `SkillData` assignment keys and distinct nested
`MinionModifier` destination names. Same-name/key order, full bodies, conditions,
duplicate multiplicity and all scalar outputs stay exact. Its three pinned
consumer excerpts explain these comparisons. They authorize no native numeric
reassociation and no retry-until-pass.

Each report captures 18 baselines, two configuration constructions, 125 actual
configuration callback invocations, 663 catalogue entries, 2,394 node
constructions, 42 node-list constructions, 1,536 skill constructions and 21
environments. Full bodies and aliases are retained before/routing phases;
callback references are explicitly distinguished from execution. Ordinary Rust
tests authenticate these archives and never execute their Lua or historical
Rust. Gzip expansion has a hard per-file limit. `CalcSetup.lua.gz` uses the
source manifest's explicit CRLF-to-LF normalization; other witness/raw bytes
remain exact.

## Still required before supplier admission

The captured recipe and constructed-body censuses find no adjustment records,
but observation alone cannot close arbitrary constructors or unexecuted
callbacks. The selected 34 quest callback constructions now reconcile to an
independently authenticated finite source matrix and 17 saved native rewards;
see `configuration-review.md`. General quest parsing and later direct
configuration consumers remain open, plus source-only versus unresolved inputs;
node/socket/radius and generated/support declarations/constructors; and later
procedural transformations and source-to-recipient delivery. Exact native
source dispositions and complete checked-query membership must then be
authored. These are explicit pending work, not inferred false flags or empty
runtime domains. The existing resource-transformation witness is referenced
without treating PoB iteration quirks as accepted game rules.

The Rust target `owned_mana_supplier_sources` reconstructs the packet and tests
direct source/writer, missing-record, duplicate, membership, provider-path,
foreign-lineage and policy refusals. Its ignored retention entry needs
`POE_MANA_SUPPLIER_RETAIN=1`; ordinary tests require neither PoB execution nor an
ignored local run directory.
