# Selected passive socket and radius construction

This offline proof reconciles the radius-provider construction boundary for the
unchanged Original05. It adds no native rule, zero producer, import disposition,
or coverage permission. The current native package is unchanged.

The input authority is the existing authenticated historical supplier snapshot
`3ee48944…`, its exact source-to-owned bindings, and the original socket-load
witness in `empty-passive-socket-intrinsics`. The selected Spec 3 has an explicit
empty socket container and 19 zero socket selections. Its 57 source nodes map
to 55 exact allocation occurrences and two separate implicit roots (8305 and
54447). Occupied archived Specs 5 and 6 remain negative controls. This historical
evidence is not a reconstruction of an old runtime or the current release.

The earlier supplier acquisition retained node bodies and final socket state,
but omitted invocation and override inputs. `owned_mana_radius_source` fills
only that gap through four fixed fresh loads: two independently observed runs
with JIT disabled, an uninstrumented JIT-disabled control, and an uninstrumented
JIT-enabled control. Original functions are not replaced. Every scalar field
captured by the existing offering-output snapshot agrees across all four loads;
this does not claim observation of every hidden scalar in PoB.

Each observed run contains 21 fresh environments (16 MAIN, one CALCS, four
CALCULATOR). Every call supplies no reusable environment, no acceleration, and
no replacement or extra-radius override. The three calculator cache inputs
contain only the recorded cached databases/full-DPS cache. Consequently, this
proof refuses reused, accelerated and otherwise overridden environments. The
complete wipe body is retained as a boundary, not claimed as an exercised path.

For every call, the verifier checks all 113 ordered slots against the complete
slot map and UI socket map. Exactly 112 actual selections reach the original
item-selection hook; Ring 3 is the sole early skip. All 19 socket candidates
have zero selections and no resolved item, and `items[0]` is absent. Other
selected items have no radius index. Together with the exact original item
gate and absent extra-function override, these inputs exclude both radius
insertion branches. Empty resulting lists alone would not establish that fact.

The original node-list consumer runs twice per environment. Each pass visits
all 57 selected nodes exactly once: 42 list calls and 2,394 node calls per
observed run. Invocation, environment, parent/list identity, relevant arguments,
and before/after radius inventories are checked. The first pass explicitly
includes keystone modifiers; the second supplies no such argument. Independent
comparison counts only the node visitation inventory, retaining full records,
duplicates and context. Raw visit order remains archived. No numerical reduction
order, slot priority or scalar result is normalized.

`radius-bodies.json` seals complete relevant bodies against the existing pinned
`CalcSetup.lua` archive: initialization, wipe, both insertion paths, node
construction, list finalization, and the equipped-jewel delivery boundary.
The original source license is retained in `upstream-LICENSE.md.gz`.

`radius-acquisition.json` contains compact metadata. The four raw load outputs
and four exact acquisition scripts are archived once. Reinserting the two raw
observations reconstructs the exact accepted report hash
`8784718a733d10878da117724b3dff69e97d380c0140bfbab1cc02ffbf11a2da`, avoiding
a duplicate 57 MB report archive. Each raw archive has explicit compressed and
decompressed bounds. Ordinary Rust tests need no live Lua or PoB checkout.

The resolved boundary is selected socket/radius construction. Ordinary passive
transformations, other item and skill constructors, later modifier delivery,
generic radius behavior, native source completeness and complete-build
availability remain separate. No empty native contribution domain is inferred
from this source result.
