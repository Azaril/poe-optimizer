# Default Timeless search-preference accounting

The maintained source manifest enables `timeless_search_defaults` in its existing
Import presentation policy. The family is bound to the pinned PoB mapping source
and the injected normal Build target version. It changes no native definition,
rule, query, value, identity allocation or inventory-completion state.

Only a unique ordinary Build with one direct, flat TimelessData child is admitted.
The child must contain exactly `devotionVariant1="1"`, `devotionVariant2="1"`,
`searchList=""` and `searchListFallback=""`. Unknown, missing, duplicate, escaped,
namespaced, nested and nondefault content stays unresolved. Even explicit
`socketFilterDistance="0"` is outside this first contract. The disposition is
`source-timeless-search-defaults`; existing semantic links cannot be displaced.

The four values are future search-tool preferences. They neither identify an
equipped jewel nor transform the current passive tree. In pinned PoB
`3887ae68a6a6b8bb7b41d1b61998f1aa184201e4`, Build initialization/load/save owns the
saved state; TreeTab.FindTimelessJewel reads it when constructing the search tool.
Its explicit Generate/Search callbacks calculate temporary alternatives and build
result rows. TimelessJewelListControl.OnSelClick creates an Item only after a
separate result-selection action. Import does not perform those operations.
