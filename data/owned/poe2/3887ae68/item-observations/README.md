# Reviewed derived display observations

This successor follows `source-role-inputs`. Six injected unsigned-integer grammars cover
Armour, Evasion, Energy Shield, Ward, Spirit and Charm Slots. They classify regenerated
preamble observations only on finite compatible template sets. They emit no game inputs
and do not establish numerical coverage.

Acquire independent source evidence with the optional reference build:

```powershell
poe-optimizer export-owned-item-observations --source-root vendor/path-of-building-poe2 --output NEW_EXPORT
```

Compile and publish through the native CLI, with no source checkout or Lua runtime:

```powershell
poe-optimizer compile-owned-item-observations PRIOR --catalog data/owned/poe2/3887ae68/item-observations/catalog.json --policy data/owned/poe2/3887ae68/item-observations/policy.json --output NEW
```

`catalog.json` is the finite authenticated projection; `evidence.json` records acquisition.
`policy.json` is reviewed grammar and family data bound to the exact catalog bytes.
`items.json`, `item-source.json` and `compiler-receipt.json` are the expected native compiler
outputs from the preceding package. All prior schema, numerical programs, definitions,
receivers and 110 original query rows stay unchanged. Existing output directories are never
overwritten. The older item-base catalog v1 remains byte-for-byte unchanged.

Defence applicability requires a compatible armour table, no active weapon branch and no
known defence-header base-retarget exception. Spirit/Charm Slots require finite corresponding
base values, including zero. Attribution separately requires an exact unique structural base,
a proven prefix, valid captures and placement before `Implicits:`. Duplicate fields, unknown
predecessors, malformed/tagged/escaped lines, wrong templates and late headers stay pending.
The compiler's exact-base count describes syntactic bindings; runtime ambiguity checks still
apply. A supplied hash establishes integrity, not independent acquisition authority.

`Corrupted` is a separate actual input and is not classified by this package. Neither are
unresolved decorated magic names inferred from fragments. Original collection/order,
allocation, missing-mechanic and numerical gates remain in force.
